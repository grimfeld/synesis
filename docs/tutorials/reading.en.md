# Reading mode

Reading mode locks your Writings against editing: nothing can be typed, and a phone's keyboard stays down. It is meant for reading a Note on the bus or a talk at the lectern without a stray tap changing it. The lock belongs to this Device and stays on until you open it.

1. Open one of your Notes with [Search](command:nav.search), then run [Reading mode](command:editor.reading). The lock in the page header closes and is highlighted. Click into the text and type: nothing changes, and a message says Reading mode is on.
2. Reading still works as before: click a link and its page opens; [Back](command:nav.back) returns to the Note. Passages and Embeds open too, and you can select text and copy it. The title, Tags and Properties are fixed, but a checkbox can still be ticked, so a checklist stays usable.
3. Open a Composition with [Search](command:nav.search) and switch to its Board with [Board](command:doc.board). It opens in **Reading** rather than **Arranging**: a click on a card opens its document. The Board's own switch still changes that for this visit.
4. Try it once: decide how this Device should open your Writings. If it is mostly for reading, leave the lock on. If you write here, run [Unlock to edit](command:editor.reading): every Writing opens for editing again, and stays that way after a restart.

## Good to know

- The lock is one setting for every Note, Clipping and Composition on this Device. Your other Devices keep their own.
- It works with Live Preview and Source mode alike. [Source mode](command:editor.source) is not offered while the lock is on, so switch to it before locking if you want to read the raw markdown.
- Delete stays in the header: it asks first, and removes rather than edits.
- The Delivery view is always locked, whatever this setting.
